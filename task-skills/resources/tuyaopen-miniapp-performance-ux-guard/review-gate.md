# Review workflow

1. Identify the requested scope and actual target/runtime acceptance criteria.
2. Read adjacent code and relevant rule/reference files. Numeric heuristics require measured target evidence before becoming blocking requirements.
3. Collect the available build, preview, console and interaction evidence. State unavailable tools or measurements explicitly.
4. Report findings by severity with file, trigger, impact and proposed correction.
5. For a requested release decision, classify actual criteria as PASS, BLOCKED or NOT VERIFIED. An explained evidence gap remains NOT VERIFIED. Quality grades and coverage counts are optional summaries, never substitutes for evidence.

Do not advance a review request into publication, or demand a new approval for routine implementation already authorized by the user.
